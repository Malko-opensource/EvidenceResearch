# 기능 실연 의뢰와 이미 알려진 상황

원래 의뢰: “누락값이 섞인 고객 응답 CSV로 팀별 만족도를 믿고 보고할 수 있는지 연구해 줘.”

이는 설치된 스킬·CLI·웹의 실제 도구 사용을 검사하는 공개 합성 데이터 개발 실연이다. 실제 고객 연구나 연구 성능 비교가 아니다. 사용자에게 전문 통계 설계를 요청하는 대신 외부 에이전트가 조사·구현·해석한다.

이미 확인된 의뢰자 정보:
- 요청자는 비전문 연구 분야의 엔지니어이며 단계, 목표 대비 지표, 관측 비용, 경과 시간, 확인된 결과를 보고받는다.
- 적용 범위는 이 실연 CSV의 기술 통계다. 다른 고객 집단에 대한 일반화·인과 효과·성능 개선은 범위 밖이다.
- 원하는 산출물은 재현 가능한 팀별 요약 코드·원본에 연결된 결과·검증·한국어 보고·재개할 목표 프롬프트다.
- 별도 채널에서 새로운 목표나 실행을 복제하지 않는다. 작업공간은 `goal-plugin-demo-20261004`이며 CLI/stdio/WebMCP의 같은 루트를 사용한다.
- 이 개발 실연의 파일 작성과 로컬 실행은 승인됐다. 네트워크·외부 모델 비용 지출·전역 설정 변경은 승인하지 않았다. 모델 사용량 및 비용은 관측할 수 없으면 unknown이다.
- 실연의 사업상 기준은 만족도 80% 이상이다. 누락 행을 제외한 값/5 ×100을 쓰며, 목표 충족과 올바른 계산 검증을 별도로 보고한다. 기준 미달도 근거가 있으면 연구 질문의 답이 될 수 있다.
- 보유 자료는 `data.csv`. 유효 평점은 1–5, 빈 평점은 누락으로 집계하고 제외한다. 단위는 백분율(percentage)이다.

재현 검증의 소유자가 실행 전 고정한 검증기는 요약 산출물로 전체 만족도, 유효·누락 행, 팀별 평균을 원본 CSV로 독립 계산한다. 에이전트는 고정 검증기를 수정하거나 검증 숫자만 제출해 통과시키지 않는다. 정확성 일치와 사업 기준 80을 모두 사전 등록한다.

표시 검사를 위한 반복은 동일 고정 입력과 동일 소스를 seed 0,1,2로 세 번 실행한다. 이는 반복 분포를 실제 산출물로 확인하는 최소 개발 fixture이며 표본 독립성·통계 검정력·모집단 신뢰구간의 근거가 아니다. 전체 연구의 반복/시간/실패 한도를 설정하는 것이 아니다. `conditions.repeat_design = three_fixed_input_replications`를 명시하고 그 밖의 조건은 동일하게 유지한다.

이 실연에서 스킬을 읽고 실제 장기 목표 프롬프트를 작성한다. 중요한 정보가 남아 있으면 이를 명시하고 필요할 때만 의뢰자에게 묻는다. 이미 제공된 답과 승인은 재질문하지 않는다. 상태 조회 → 기억 검색 → 목표 저장 → 가설 → 사전등록 → 코드·실행 → 독립 검증 → 결정 → 완료/재개 보고를 실제 CLI로 수행하고 호출·출력을 그대로 보존한다.
