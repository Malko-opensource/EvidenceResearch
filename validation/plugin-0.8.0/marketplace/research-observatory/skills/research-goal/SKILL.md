# 연구 의뢰를 장기 목표로 설계하기

원래 의뢰를 보존하면서 외부 에이전트가 계속 수행하고 중단 후 재개할 목표 프롬프트를 만든다. 사용자는 연구 전문지식을 요구받지 않고 단계·지표·비용·시간·결과를 보고받는 엔지니어다. 확정된 페르소나와 보고 항목은 다시 인터뷰하지 않는다.

이 스킬은 외부 에이전트의 지침이다. 모델 호출·조사·가설·실험 코드·다음 행동·해석은 외부 에이전트가 담당한다. 도구는 영속 상태·사전등록·증거·검증·기억을 관리한다. 프롬프트 작성 요청이면 프롬프트를 산출하고, 연구 수행까지 승인돼 있으면 그 범위에서 이어간다. 스킬 사용·플러그인 설치·프롬프트 생성만으로 실행 권한을 추정하지 않는다.

## 의뢰를 구체화하기

기존 대화와 자료에서 원래 요청, 적용 상황, 산출물·완료 기준, 범위, 이용 가능한 자료·환경, 실행 권한과 실제 자원 조건을 찾는다. 확정 사실, 명시적 가정, 미확인 사항을 구분한다.

사용자가 답할 수 있고 답에 따라 목표나 권한이 달라지는 중요한 누락부터 질문한다. 산출물·적용 상황·보유 자료·권한·실제 예산 같은 질문이 여기에 해당한다. 가설 선택, 전문적인 통계·실험 설계, 검증 코드 작성은 에이전트가 조사하고 근거를 들어 제안한다. 사용자에게 전문적 결정을 전가하지 않는다.

중요하지 않은 빈칸은 영향과 확인 방법을 남긴 가정·미확인으로 진행할 수 있다. 핵심 목표·권한·큰 비용을 좌우하는 미확인 항목에 의존하는 실행은 시작하지 않는다. 허용된 독립 조사·상태 조회는 계속한다. 이전 답변이나 실행 승인을 반복해서 확인하지 않는다.

[목표 프롬프트 양식](references/goal-template.ko.md)을 읽고 실제 의뢰로 채운다. 예시 수치와 빈칸을 사실처럼 남기지 않는다. 최초 가설과 계획은 수정 가능한 제안이다. 목표의 의미·범위 변경은 변경 이력으로 남기며 기존 권한을 벗어나는 변경만 확인한다.

연구 질문에 답한 것과 원하는 성능 개선을 입증한 것은 다르다. 근거 있는 부정적 결과가 완료가 될 수 있는지는 의뢰의 완료 기준으로 판단한다. 실행 성공·형식 검사·에이전트의 자신감을 과학적 성과로 바꾸지 않는다. 효과를 주장하려면 같은 조건의 사전등록 비교와 실제 독립 검증이 필요하다.

전체 연구에 임의의 반복 횟수·시간·연속 실패 한도를 붙이지 않는다. 실험 반복 수는 해당 평가의 불확실성과 실제 자원 조건에 근거를 두고 실행 전에 등록한다.

## 같은 연구를 도구로 이어가기

첫 도구 사용 또는 채널 전환 전에 [채널 연결 계약](references/channel-contract.ko.md)을 읽는다. 설치된 도움말과 실제 스키마를 우선한다. 연결된 절대 root와 상대 workspace를 명시하고 상태·목표 버전·관련 성공·실패·미결 기억을 조회한다.

목표를 새로 저장할 때 안정된 request key와 최신 revision을 사용한다. 이미 있는 목표는 원본 ID와 버전을 이어간다. 프롬프트 파일과 목표 DB는 별도 산출물이며 파일과 DB 사이의 원자성을 주장하지 않는다. 채널을 바꿔도 목표와 실행을 복제하지 않는다.

실험 전에 가설·변경점·비교·분할·seed·소스·지표·기준·실행 조건과 고정 검증기를 사전등록한다. 조건 변경은 새 등록이며 기존 기준을 덮어쓰지 않는다. 검증기 등록은 owner의 허용된 로컬 CLI 작업이다. 에이전트 도구에 없는 관리자 기능을 우회하지 않는다.

실제 명령·로그·측정·산출물과 원본 증거를 연결하고 등록된 검증기로 확인한 뒤 판단과 적용 범위를 남긴다. 실행 성공, 검증 통과, 가설 채택, 원본 해시 일치는 서로 다른 사실이다. 실패·미결·반대 증거를 보존한다. 실행 실패만으로 가설이 반박됐다고 하지 않는다. 같은 원본을 여러 번 연결한 것을 독립 반복 확인으로 세지 않는다.

응답이 끊기거나 실행 여부가 unknown이면 원 실행의 상태·증거를 확인하고 recover로 수집한다. 자동으로 대체 실행을 시작하지 않는다. 같은 요청은 같은 request key로 재전송하며 충돌 시 최신 원본을 조회한다. 외부 부작용의 exactly-once 실행을 보장한다고 주장하지 않는다.

## 보고·변경·재개

현재 단계, 목표 대비 실제 지표와 한 줄 해석, 누적 비용의 집계 범위, 경과 시간, 확인된 결과·검증 상태를 먼저 보고한다. 확인할 수 없는 외부 모델 사용량과 비용은 unknown이다. 연구 종료·중단 시에는 사유·확보 결과·미완료 범위·총비용·시간을 앞에 둔다.

WebMCP에서 요약 → 질문에 맞는 분석·비교·관계·분포·자원 장면 → 필요할 때 원본 증거 → 요약으로 설명한다. 사람의 클릭을 필수로 만들지 않는다. 실제 지원 장면만 사용하고, 원본에 없는 과학적 관계나 가짜 진행률·연구 품질 점수를 만들지 않는다. 서로 다른 조건은 같은 순위로 비교하지 않는다. 독립 검증 여부와 반대 증거·누락을 유지한다.

방법 변경은 이유와 차이를 기록하고 목표의 의미·범위 변경은 새 목표 버전으로 남긴다. 종료 보고는 외부 에이전트의 보고이며 실험 검증을 대신하지 않는다. 재개할 때 목표 버전, 마지막 상태·시점, 미완료 질문, 원 실행 식별자, 필요한 증거와 다음 허용 작업을 확인한다. 기억·설명만으로 완료를 추정하지 않는다.

최종 산출물은 짧은 의뢰 해석과 주요 가정, 목표 프롬프트, 필요한 미확인 질문, 원본 연결 정보와 재개 안내다. 도구 기능 검사, 화면 설명 개선, 연구 성능 개선의 입증을 구분해 보고한다.
