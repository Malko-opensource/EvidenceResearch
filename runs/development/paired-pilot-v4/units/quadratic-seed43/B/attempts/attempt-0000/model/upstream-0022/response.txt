# Curvature Versus Shrinkage in Polynomial Regression

A fixed-split study comparing polynomial flexibility and ridge regularization. The repository documents a preregistered comparison protocol and one host-verified baseline result.

**Current status:** Only the unregularized quadratic has supplied measurements. Whether shrinkage or additional polynomial terms improve prediction remains unresolved.

## Task and Data

| Property | Value |
|---|---|
| Public task | `dev-quadratic` |
| Task version | `polynomial-ridge-1` |
| Seed | 43 |
| Training observations | 80 |
| Validation observations | 64 |
| Test observations | 96, withheld |
| Configurable degree | Integer from 1 through 8 |
| Configurable regularization | Finite `alpha` from 0 through 100 |

Each observation contains an identifier, a scalar predictor `x`, and a scalar response `y`. Candidates use the original splits and the host's existing preprocessing and polynomial ridge implementation. Coefficients are fitted exclusively on training observations.

The supplied evidence does not specify feature scaling, intercept treatment, penalty normalization, solver details, or the response-generating equation.

## Research Question

Does coefficient shrinkage or additional polynomial flexibility reduce validation mean squared error (MSE) relative to an unregularized quadratic?

The working hypothesis is that degree two captures the apparent curvature and that additional terms may fit noise. This remains a hypothesis requiring measured comparisons.

## Comparison Protocol

The preregistered candidate sequence is:

| Order | Degree | Alpha | Status |
|---|---:|---:|---|
| 1 | 2 | 0.0 | Measured |
| 2 | 2 | 0.1 | Proposed |
| 3 | 2 | 1.0 | Proposed |
| 4 | 3 | 0.1 | Proposed |
| 5 | 4 | 1.0 | Proposed |
| 6 | 1 | 0.1 | Proposed |
| 7 | 2 | 10.0 | Proposed |
| 8 | 8 | 10.0 | Proposed |

Candidates are submitted individually, in order, until the sequence is complete or a host resource constraint prevents further execution.

Selection minimizes actual host-measured validation MSE among distinct evaluated configurations. Exact ties are resolved first by lower degree, then by lower `alpha`. Training MSE is recorded as a diagnostic and does not determine selection.

Within-degree comparisons assess shrinkage. Comparisons at a shared numerical `alpha` assess changes in representation, although effective shrinkage can differ across degrees. Comparing `(8, 10.0)` with `(2, 0.0)` changes both flexibility and regularization and cannot isolate either factor.

The unregularized quadratic is provisionally selected because it is the only measured configuration. Similar training and validation errors are consistent with its performance transferring to this validation split, but do not establish superiority over alternatives.

## Host Submission Interface

The measured configuration was submitted as:

```python
CONFIG = {'degree': 2, 'alpha': 0.0}
```

This is a configuration request for the trusted host, which performs training and evaluation using preloaded data.

The interface accepts one literal `CONFIG` assignment or one standalone `run_candidate` call per action. Only `degree` and `alpha` are legal fields. Imports, loops, functions, arithmetic expressions, filesystem access, printing, custom preprocessing, and alternative training implementations are outside the execution contract.

Cached replay does not count as a new CPU attempt. Figures, external datasets, API calls, and arbitrary code execution are also outside the permitted experiment interface.

## Interpretation and Limitations

The available evidence does **not** establish that:

- Quadratic curvature is necessary.
- Higher-degree polynomials overfit.
- Positive regularization is ineffective.
- The selected configuration is globally optimal.

No confidence intervals, significance tests, independent statistical replications, test-set measurements, runtime comparisons, monetary costs, or measured improvements over alternative configurations are supplied.

Reported decimal precision reflects the numerical execution record, not statistical certainty. Reusing validation observations for configuration selection can make the eventual selected validation score optimistic. Preregistering the sequence makes the search reviewable but does not remove this effect.

The host lists specification, split-manifest, model, prediction, and execution-log artifacts as provenance. Their contents were not independently inspected for the report.
