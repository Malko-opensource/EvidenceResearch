# Polynomial Degree and Ridge Regularization

A fixed regression study comparing polynomial complexity and ridge regularization on the seed-19 `dev-linear` task.

**Status:** One configuration has supplied valid host measurements. The planned nine-candidate comparison remains incomplete.

## Research Question

Does ridge regularization change the validation ranking of polynomial degrees?

The training observations motivate the hypothesis that a degree-one model with weak regularization will perform well. This is a hypothesis, not an established description of the generating function.

Feature scaling, solver details, intercept treatment, and penalty normalization are not sufficiently documented in the supplied record. Penalties therefore refer to the host's parameterization.

## Experimental Protocol

The preregistered candidate set is:

- Polynomial degree: `1`, `2`, or `3`.
- Ridge penalty: `0.0`, `0.1`, or `1.0`.

Candidates are evaluated in the order shown below. Each model is fitted exclusively on training observations.

Selection minimizes validation mean squared error (MSE) among completed valid evaluations. Exact ties are resolved by lower degree, then lower penalty. Rounded display values do not determine ties.

If resource limits prevent completion, selection uses the completed prefix of the planned sequence. After selection, the configuration is frozen without further validation-guided refinement.

## Host Execution Contract

Candidate evaluation is performed by the trusted host. An evaluation submission must contain one literal configuration assignment or one standalone `run_candidate` call.

The provisional selected configuration is:

```python
CONFIG = {'degree': 1, 'alpha': 0.0}
```

The only legal fields are:

| Field | Host-permitted values | Study values |
|---|---|---|
| `degree` | Integer from 1 through 8 | 1, 2, 3 |
| `alpha` | Finite number from 0 through 100 | 0.0, 0.1, 1.0 |

Each permitted action evaluates one candidate. Imports, loops, functions, arithmetic expressions, filesystem access, printing, and other Python statements are prohibited. Data are preloaded, so data-preparation submissions use the same literal configuration form. Model replacement or editing follows the same restriction.

Cached replay does not count as a new CPU attempt. Figures, external datasets, API calls, and arbitrary code execution are outside the shared permissions.

## Planned Comparisons

After the remaining eight candidates receive valid host measurements, the study will compare:

- **Degrees within each penalty:** differences in validation MSE identify degree rankings. A change in the sign of a pairwise difference across penalties documents a ranking reversal.
- **Penalties within each degree:** validation MSE relative to that degree's unpenalized candidate identifies measured regularization benefits or losses.

Missing scores are unavailable measurements, not zeros or failed evaluations. No comparative conclusions can currently be drawn.

## Limitations

The evidence does not establish an optimal degree, a regularization benefit, or a degree–regularization interaction.

Validation observations guide selection, so the selected validation score is not an independent generalization estimate. No test measurements, confidence intervals, significance tests, timing comparisons, monetary costs, or measured improvements over alternative configurations are supplied.

Results remain conditional on the fixed dataset splits, candidate set, and host fitting conventions.
