# 등록 전 v5 보고서 검증 설계

메인 v4의 실행·소스·기준은 그대로 보존한다. 이 문서는 별도 개발 버전의
검증 계약이며 프레임워크 개선을 입증한 결과 보고서가 아니다.

숫자만 검사하면 “기존 방법보다 우수하다”, “기억이 향상을 유발했다”,
“독립적으로 재현했다” 같은 문장을 놓칠 수 있다. v5는 본문 문단과
JSON의 키·문자열·scalar 항목을 원본 위치와 해시로 목록화한다.
독립 검토자는 비공백 내용 전체를 겹치지 않는 주장 span으로 분류하고
측정·실행·문헌·추론·제안·방법·한계의 적용 범위를 설명해야 한다.

실제 측정 주장에는 고정 검증기를 통과한 실행을 연결한다. 비교 주장은
동일 조건의 서로 다른 실행을 요구하고, 관찰된 최선이라는 주장은
실제 완료 실행 목록 전체에서 선택된 검증 지표의 최솟값을 재계산한다.
단일 실행의 정상 완료만으로 상대적인 성능 향상을 지원할 수 없다.
문헌은 등록된 자체 작성 요약의 정확한 범위와 출처에 연결하며,
문헌 주장을 이번 과제의 측정값으로 변환하지 않는다.

인과적인 기억 효과, 일반적인 프레임워크 우월성, 모델 교체 효과는
별도 고정 비교 증거 없이 지원 판정할 수 없다. 독립 재현을 지원할
고정 재현 증거 adapter가 없는 경우에도 보류 또는 미지원으로 남긴다.
검토자가 방법·한계·제안으로 표시했다는 이유만으로 인식된 결과
주장을 제외할 수 없으며, 다른 문장의 “No”나 “propose”가 실제
결과 문장을 완화하지 못하도록 구체적인 회귀 검사를 추가했다.

고정 predicate는 출처·계산·조건의 일치를 검사한다. 자유로운 자연어의
모든 의미를 자동으로 증명하지 않으며, reviewer role 문자열만으로
독립된 사람의 신원을 인증하지 않는다. 모든 결과 주장을 찾아 정확한
predicate에 대응하는 책임은 독립 검토자에게 있다. 이 한계를 평가
정책에 기록한다.

양쪽 arm의 원본 본문과 공통 companion은 수치 검사와 의미 검사 모두를
통과해야 한다. 미지원과 보류를 각각 보존하고 하나라도 남으면 채택
조건을 충족하지 못한다. 수정된 검토는 새 버전 sidecar로 저장하며
이전 보류 판정과 완료된 실행 증거를 덮어쓰지 않는다. 검토가 완료돼도
기존 측정 지표·원시 자원 값을 바꿀 수 없다.

최종 소스와 정책을 고정한 뒤 별도 개발 과제를 등록한다. 등록 후 발견한
실행 설계 문제를 같은 연구의 기준 변경으로 해결하지 않고 다음 버전과
새 과제로 넘긴다. 개발 검사와 최종 과제에서의 개선 검증은 별개다.
