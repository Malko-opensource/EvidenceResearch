# v7 개발 후보의 범위와 검증 한계

이 문서는 `c7-full-check-v2/s/docs/c7_development_status.ko.md`에서 방법과 검증 범위만 정리한 공개용 파생 문서다. 원본 문서의 실제 진행 중 연구에 관한 구체적인 판정 수와 연결 경로를 포함하지 않는다. 원본 파일은 과거 검증 snapshot에 보존한다. 새 릴리스에 파생 문서를 쓰면 원본과 다른 바이트임을 release-copy 영수증의 명시적 문서 override로 기록한다.

후보 패키지 버전은 `0.4.0.dev0`이다. 부모가 보존한 전체 공학 검사는 263개를 통과했고 검사의 전후에 소스 108개와 보호된 기존 소스 309개가 일치했다. 모델 호출이나 실제 연구 과제는 이 검사에 포함되지 않았다. 별도의 독립 사례 검토와 새 환경 설치 검증이 완료되기 전에는 새 릴리스가 동결되었다고 주장하지 않는다.

공통 ContextBoundary는 각 원래 모델 요청 직전까지 완료된 실제 요청·실험 기록과 그 요청에 실제 들어 있던 값·문장을 연결한다. 이후의 전체 기록을 과거 입력으로 바꾸어 설명하지 않는다. 원본 Agent Laboratory 단계, 원래 모델 본문, 기존 연구 결과와 판정은 변경하지 않는다. 합성 자료는 구성 검사에만 쓸 수 있으며 실제 연구 채택 근거로 승격하지 않는다.

입력에 문헌이나 지표 값이 있었음을 확인하는 것은 에이전트가 그것을 읽고 이해했다는 증거가 아니다. 제한된 산술 검증은 통계적 유의성, 일반화 또는 인과 효과를 입증하지 않는다. 범위가 불명확한 문장, 지원되지 않는 표현, 누락된 논리 매핑과 사용량은 판단 보류 또는 미상으로 남긴다. 계정 인증과 실제 모델 실행 능력은 새 환경의 CLI 상태 검사만으로 확인되지 않는다.

향후 실제 비교는 같은 과제·모델·권한·자원 상한과 사전에 동결한 독립 품질·비용 기준을 따라야 한다. 공학 검사 통과만으로 프레임워크의 개선이나 모델 교체 효과를 선언하지 않는다. 별도의 새 개발 자료와 최종 평가를 구분하고, 과거 실패를 새 기준으로 소급 채택하지 않는다.
