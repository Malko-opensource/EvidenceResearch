# c9 보고서와 재개 상태의 통합 계약

구현 전 등록된 새 개발 후보다. 원 B 알고리즘·prompt와 같은 모델·도구·자원 조건, 채택 기준을 보존한다. 원 실험과 보고서·독립 판정은 변경하지 않는다. 작성자 검사, 별도 독립 검증, 실제 연구 비교는 다른 증거다.

공통 historical numeric 판정은 전체 원 보고서 단위와 모든 숫자, 원 입력 경계와 당시 prefix를 재계산한다. C 표시기는 시간만 명시적인 ROUND_HALF_EVEN으로 소수점 아래 최대 12자리까지 표시한다. 원 기록과 비교 값은 반올림하지 않는다. 알려지지 않은 값은 표시 숫자에서 제외하고 unknown 목록에 보존한다. 순수 표시 함수는 증거를 인증하지 않는다. 실제 호출자는 원 boundary 감사가 eligible true, fixture false, pending 없음인 경우에만 measured 표시를 만든다.

실행 성공과 등록된 incumbent 기준의 채택을 구분한다. 동점이나 strict 개선량과 같은 차이는 기준 미달이다. 기술적 오류의 원문은 유지한다. 불충분한 비교의 inconclusive는 가설 판단이 unknown임을 명시하고 실패 기준으로 바꾸지 않는다. 언어모델·고정 실행기·별도 평가 함수의 역할 설명은 각 설계 규칙 문단이며 실제 완료나 독립 재현을 주장하는 증거가 아니다.

원 가설·선택 이유·stop 문구는 그대로 유지한다. 원 응답을 연결했다는 이유로 그 안의 과거 결과·인과·일반화·비용 주장을 사실로 취급하지 않는다. 원문 전체의 factual 내용은 별도 numeric·semantic 검토 대상이다. 지원하지 못한 내용은 pending 또는 unsupported로 남으며 authorship이나 proposal 라벨로 승인하지 않는다. 이 후보의 유한 문법이 모든 자유 문장을 해석한다고 주장하지 않는다.

판정이 끝난 보고서 거절과 아직 끝나지 않은 검토를 구분한다. terminal report_rejected는 실행의 CPU 성공 자체를 실패로 바꾸지 않는다. 저장 score는 실제 원 산출물·raw 계약·두 보고서의 numeric coverage·semantic 감사와 대조한 뒤 사용한다. 저장된 bool이나 decision 문자열만 바꾸어 완료·채택으로 승격할 수 없어야 한다. 기존 paired 채택과 분산 입력 기준은 유지하며 거절을 제외한 부분집합을 새 성공률 증거로 제시하지 않는다.

새 SEM4·quality5·efficiency8 및 패키지0.5.0.dev0은 미래 등록에서 고정한다. 과거 판정에는 적용하지 않는다. 신규 실제 연구와 최종 평가, 현재 모델 B/C 개선은 아직 미입증이다. A 원 모델 계열의 교체 효과도 추정하지 않았다. 변경된 reporting·공통 지원을 함께 비교하면 각각의 원인 효과는 분리되지 않는다.
