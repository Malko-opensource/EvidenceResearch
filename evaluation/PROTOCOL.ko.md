# 사전 등록: CSV feasibility 비교 v1

2026-10-04(한국 시간)에 외부 에이전트 실행 전에 이 문서, `protocol.json`,
고정 평가기, 과제 브리프·초기 코드·입력을 고정한다. `frozen_manifest.json`에
각 파일 SHA-256을 기록한다. 이후 수정은 v1 결과를 덮어쓰지 않고 새 프로토콜이다.

## 비교와 표본의 의미

주 비교는 F1 가중 평균·분산, F2 불규칙 시간창 평균 각 한 쌍이다.
B는 기존 Codex 에이전트와 현재 모델, C OFF는 동일 에이전트·모델과 연구 CLI다.
F1 순서는 B→C OFF, F2는 C OFF→B다. 기억 효과는 별도 M1/M2 이벤트 중복
요약 입력 변형에서 각각 C OFF→C ON, C ON→C OFF 한 쌍으로 비교한다.
M1/M2는 한 과제의 입력 변형이며 독립 과제 두 개로 해석하지 않는다.
개발용 D는 CLI 연결 점검에만 사용하고 최종 결과에서 제외한다.
기억 시드용 M_PRIOR도 별도 입력·평가 사례의 개발 과제이며 최종 비교 지표에서 제외한다.

두 수치 오류와 기억 적용 조건을 작은 실제 흐름에서 한 번씩 확인하는 feasibility
범위라서 이 수를 선택했다. 효과크기, 검정력, 통계적 개선을 입증하는 표본 수가 아니다.
이는 이번 비교의 사전 정의된 작업량이며 전체 연구의 반복 횟수·실행 시간·연속
실패 한도가 아니다. 실제 자원·권한 제한과 사용자의 중단 지시를 따른다.

각 episode는 `fork_turns=none`인 새 외부 하위 에이전트가 수행하며 부모의 모델과
추론 설정을 동일하게 상속한다. 정확한 서비스 모델 식별자가 관측되지 않으면 그
식별자는 unknown으로 남기고 추측하지 않는다. 모델 호출은 외부 에이전트 책임이다.
CLI 코드에는 모델 호출·인증·대화·자율 연구 루프가 없다.

## 같은 조건과 기억 처리

각 쌍은 같은 브리프, 초기 `solution.py`, 공개 `input.csv`, Python 런타임, 도구의
파일 접근 권한, 표준 라이브러리 의존성, 평가 계약, 성공 기준을 받는다. 조건마다
새 작업 폴더를 사용하고 다른 조건의 답안을 읽지 않는다. B는 CLI를 사용하지 않지만
일반 파일로 사전 등록·실험 기억·재개 장치를 만들 수 있다. CLI 추가만 주 처리 변수다.
같은 구체 실험 요청의 반복이 추가 실제 실행을 만들지 않도록 두 조건 모두 요구한다.
코드·입력·조건을 바꾼 정당한 새 실험은 중복으로 세지 않는다.

C ON에만 이전의 실제 실패 실험을 제공한다. M_PRIOR는 최종 M1/M2와 입력 파일·고정
평가 사례를 분리하며, 그 결과는 최종 과제의 성능으로 세지 않는다. 그 실험은 전체 행 일치로 중복을
제거하면 event_id가 같은 수정 측정을 제거하지 못한다는 실패를 고정 평가기로
확인한 기록이어야 한다. 적용 조건, 검증 실패, 실행·산출물·원본 해시를 함께 보존한다.
C OFF 저장소에는 이전 기록을 시드하지 않는다. ON/OFF가 동일한 초기 파일을 받고,
기억 검색으로 추가 정보가 들어오는 차이를 기억 처리 변수로 공개한다.

## 고정 과제와 검증

외부 에이전트는 `solution.py`의 `summarize(rows)`를 작성한다. `task.py`가 공개
CSV를 읽고 실제 함수를 호출하여 `result.json`과 `invocations.jsonl`을 기록한다.
소스·입력·task.py 해시와 명령을 실행 전에 고정한다. 변경은 새 등록이다.

`fixed_validator.py {bundle}`은 보존된 `solution.py`를 별도의 새 로컬 Python
프로세스에서 고정 사례마다 실행하고, 독립 Decimal 기준값과 비교한다. 실행 결과도
보존된 입력 CSV의 기준값과 대조한다. 에이전트가 제출한 pass_rate나 성공 선언은
평가에 사용하지 않는다. 산출물은 result.json, invocations.jsonl, solution.py,
input.csv다. core가 고정된 `pass_rate >= 1.0` 조건을 적용한다.
수치 허용오차는 절대 1e-8과 기준값의 double 정밀도 두 단계다.

평가 사례·평가기 구현·다른 조건 답안을 에이전트가 읽지 않는 것은 평가 규약이다.
동일 OS 계정의 읽기를 막는 보안 격리라고 주장하지 않는다. 검증 대상은 신뢰하는
로컬 과제 코드이며 악성 코드 실행 샌드박스는 제공하지 않는다.

## 측정과 판정

고정 평가기 통과율과 완전 통과 여부, 동일 조건의 추가 invocation 수, 오류 복구,
증거 없는 검증·채택 주장, 외부 episode 벽시계 시간과 확인 가능한 토큰 사용량을
원본 결과에 연결한다. 복구 상황이 없으면 not_observed이며 성공 0/실패 0으로 효과를
추정하지 않는다. 외부 사용량을 확인할 수 없으면 `status=unknown,value=null`이다.
벽시계 시간에는 모델 변동과 호스트 스케줄러 영향이 있으므로 기술적 측정만 보고한다.
임의 가중치의 종합 점수로 연구 판단을 대체하지 않는다.

기능 채택에는 모델 없는 계약 검사 전체 통과와 실제 C 에이전트의
상태 조회→기억 검색→가설→등록→실행→독립 검증→결정→기억 조회가 필요하다.
연구 성능 개선은 기본 `unproven`이다. 이 작은 표본만으로 일반적 개선을 채택하지
않으며 실패·미결도 보고한다. 결함을 수정하면 원인·증거를 남기고 새 조건을 등록한다.
이 결과를 원 Agent Laboratory 전체와의 직접 비교라고 부르지 않는다.
