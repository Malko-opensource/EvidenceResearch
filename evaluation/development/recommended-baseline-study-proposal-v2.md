# 권장 원본 설정의 자원 봉투 확대 제안(v2)

미등록·미실행 계획이다. 현재 최소전이 파일럿은 유지한다. v1의 common51 초안은 원본 문헌5/solver3/1 완료 직전에 자원을 소진할 위험이 있어 본 v2와 구분해 보존했다. 후속 등록 및 새 모델 실행은 루트가 승인된 자원 상태와 제약을 확인하고 수행한다.

공통 상한을 기존51에 맞추려고 원본 phase100을 다시 작게 만들지 않는다. 원본의 명시적 phase범위를 모두 보존하려면 문헌101 + 계획200 + 준비200 + 해석200 =701 요청까지 허용하는 것이 소스에 맞다. MLE는 최초1+solve2×유효trial2 =5개 trial에 각각 generation1+judge≤2+source repair≤2 =5요청을 배정하고 채택 reflection≤2를 더해27이다. 초기보고서는 scaffold/section9 + 문헌검색5×원본최대시도6 =39, Paper1의 최소유효수정3×generation/judge2 =6, README1+reviewer3 =4다. 합 **777 모델 요청**을 양쪽에 같은 최대조건으로 제안한다. CPU최대도 요청당 허용한 literal한구성 실행에 근거해777로 맞춘다.

이777은 모든 원본의100단계 명시적 허용범위와 source내부2수리의 유효trial경로를 보존하는 **조건부 계산**이다. 원본 MLE outerretry, 초기보고서 sectionretry, Paper editretry는 명시적 유한 상한이 없으므로777도 원본 전체 실행의 완료보장 상한이 아니다. 숫자의 근거 줄·계산·전제는 v2 JSON에 있다. 공통 자원을 다 쓰면 해당 개발 과제를 예산 내 미완료/실패로 기록하고, capacity에 의한 외부중단과 구분한다. Goal전체를 종료하거나 기준을 소급 바꾸는 숫자가 아니다.

실제 정상경로는 훨씬 작을 수 있다. 첫 최소 B관찰26 +추가 문헌 SUMMARY/FULL/ADD12 +MLE추가8 +Paper추가6 +reflection2 =54 요청은 정상경로 참고 계산이고, 두역할대화를 모두 사용하면3 정도 더 발생할 수 있다. 이 예상은 실행값·가격·시간·엄격상한으로 보고하지 않는다. 두 arm 모두777을 의무적으로 소비하지 않으며, B의 원본 완료/C의 근거있는 중단이면 실제사용으로 끝낸다. 실제tokens/time/CPU와 실패시도는 별도 독립 계상한다.

적어도 distinct5의 문헌입력이 필요하다. 루트가 기존3편에 추가할 Hoerl/Kennard1970(DOI10.1080/00401706.1970.10488634)과 Craven/Wahba(DOI10.1007/BF01404567)의 원문을 직접 검토하고 있다. 완료된 새문헌snapshot/hash를 동일B/C에 공급한 후 새source동결·등록한다. 현재3편을 중복추가해5편으로 부르지 않는다.

원본 README권장 MLE3/Paper1/lit5, constructorphase100의 정확한 출처와 기본Paper5와의 차이, 새seed9개, 적응된 CPU도구/AgentRxiv한계, A미실행은 기존 v1문서와 같은 범위다. JSONwrapper는 직접CLI실행 파일이 아니며, 예산소진분류와 문헌확장, 새동결검증 전에는 등록할 수 없다.
