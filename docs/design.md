# 설계

EvidenceResearch는 Agent Laboratory의 문헌 조사 → 계획 → 실험 → 해석 → 보고 흐름과
AgentRxiv의 검색·재사용을 출발점으로 삼는다. 원본 구현과의 관계·차이는
[원문 근거](sources.md)와 [원본 실행 어댑터](baseline.md)에 기록한다.

연구 상태는 SQLite에 저장한다. OBSERVE → RETRIEVE → PROPOSE → REGISTER → IMPLEMENT
→ EXECUTE → VERIFY → DECIDE → UPDATE_MEMORY 전이를 해시로 연결한 감사 사건에 남긴다.
사전 등록은 과제, 데이터 분할, seed, 설정, 구현·평가 해시, 모델, 자원·도구 조건,
가설, 지표, 채택 기준을 포함한다. 완료 실행과 증거는 저장 API와 SQL trigger로
수정을 거부하고 재개할 때 해시를 검사한다. 동일 실행 조건은 가설 설명을 바꿔도
재사용한다. 실행 완료 영수증이 있으면 재실행 없이 검증을 이어 가며, 영수증이
없어 실행 여부가 불명확하면 원인 확인을 요구한다.

연구 기억에는 성공, 실패, 미결 결과와 적용 조건, 검증 상태, 원본 증거를 저장한다.
검색 결과와 문헌 주장은 새로운 측정값이 아니다. 수치 주장은 measured, literature,
inference, proposal로 구분한다. 가설 선택 점수는 관련성·증거·비용·불확실성의
계획 판단이며 예상 성능으로 보고하지 않는다. 실패 재시도에는 바뀐 조건과 이유가
필요하다. 최선의 결과는 독립 검증과 등록 비교 기준을 통과한 결과로만 갱신한다.

설계자는 `ResearchProposer`, 구현자는 `tasks.run_task`, 검증자는 `verifier.verify`다.
초기 과제는 CPU 다항 ridge 회귀이며 후보가 degree와 alpha만 전달한다. 후보의
임의 Python·셸을 실행하지 않는다. 고정 실행기와 별개의 수치 해법으로 모델을
재현하고 저장된 예측에서 지표를 계산한다. 임의 코드 생성 연구까지 확장하려면
독립 OS sandbox 및 평가·증거 저장소의 별도 접근 통제가 필요하다.

Codex 모델은 별도 공개 작업 경로에서 읽기 전용으로 호출한다. 도구 호출을 금지하고
JSONL에서 도구 사용을 발견하면 해당 실행을 비교에서 제외한다. 이는 읽기 자체를
완전히 차단하는 보안 경계라는 주장이 아니다. 최종 평가에는 파일 도구 없는 모델
제공자 또는 모든 호출의 무도구 감사 증거가 필요하다. 자격증명을 복사하거나
로그·저장소에 남기지 않고 기존 로그인만 사용한다. 원본 baseline도 같은 후보
실행 도구와 데이터 권한을 받으며 원본 모델 심사 점수와 독립 측정값을 구분한다.

전체 연구 루프에 반복·시간·연속 실패 한도를 두지 않는다. 개별 비교 실험의 자원
예산과 반복 수는 사전 평가 설계로 결정하며, 정체 시 실패 원인을 분석해 다른
가설이나 검증 방법으로 전환한다. 개발 목표 달성과 사용자 Goal 완료는 별개다.
