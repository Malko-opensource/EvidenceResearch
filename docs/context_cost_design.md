현행 개발 실험에서 관찰한 문맥 비용과 다음 버전의 설계

현재 등록된 비교의 코드, 실행 조건, 원본 지표를 수정하지 않았다. 개발 복사본 `work/next-version`에만 아래 변경을 구현했다. 이 문서는 개발 관찰과 구현 검증을 기록하며, 프레임워크 개선이나 토큰 절감이 입증되었다는 보고서는 아니다.

첫 C 과제의 읽기 전용 [완료 시점 감사](../evidence/c-live-audit-v4/20261002T152934932898Z/audit.json)는 실제 모델 요청 29회, CPU 실행 28회를 확인한다. 선택한 degree=1, alpha=0.4305의 validation MSE는 0.0077919618179834735이며, 동일 조건의 완료된 실행 가운데 고정 검증기로 계산한 최솟값과 일치한다. 이 지표는 공개 검증 자료의 측정값이다. 최종 일반화 성능, 전역 최적성, 기억의 인과 효과를 뜻하지 않는다.

실제 원시 모델 기록에서 확인한 문맥 성장의 예시는 다음과 같다. 문자 길이와 모델 입력 토큰은 다른 측정이다. 입력 토큰에는 공개된 JSON 밖의 제공자 문맥도 포함되므로, 문자 증가가 토큰 증가의 전부를 설명한다고 가정하지 않는다.

| 요청 ID | 제공된 기억 기록 수 | JSON prompt 문자 | 반복 conditions 문자 | 실제 입력 토큰 | 실제 출력 토큰 |
|---|---:|---:|---:|---:|---:|
| improved-0000 | 0 | 18,723 | 0 | 26,328 | 869 |
| improved-0010 | 10 | 91,381 | 63,253 | 44,681 | 400 |
| improved-0024 | 24 | 193,861 | 151,810 | 70,504 | 527 |
| improved-0028 | 28 | 223,278 | 177,115 | 77,902 | 321 |

행별 원본 경로와 해시는 [context_cost_observations](../evidence/c-live-audit-v4/20261002T152934932898Z/audit.json)에 있다. 완료된 요청의 원시 합계는 입력 1,510,099 토큰, 출력 12,590 토큰, 모델 벽시계 시간 654.407초다. 캐시 입력 420,096 토큰은 입력의 하위 정보이며 합계에 다시 더하지 않는다. 제공자 청구 가격은 알 수 없다. 이 합계는 해당 과제의 실제 비용이며, 다른 과제나 미래 구현의 비용 예측치가 아니다.

기억의 `conditions.resource_envelope`가 모든 기록에 공통 도구 설명과 문헌 본문을 반복했다. 모델의 `normalized_cost`는 계획 판단이므로 이 실제 비용 증가를 측정한 값으로 해석할 수 없다. 또한 같은 검증 자료에서 연속적인 alpha 미세 탐색을 수행하면 아주 작은 검증 오차 차이에 과도하게 적응할 수 있다. 이 위험은 관찰과 실험 설계상의 이유로 기록한다. 현재 자료만으로 검증 과적합이 실제 발생했다고 판정하지 않는다.

다음 버전의 구현은 원본 증거를 삭제하지 않고 요청의 직렬화만 줄인다.

- 기억은 task/version/model/seed/metric, 소스·평가기·데이터·분할 해시, 전체 자원 조건 해시, 실행 fingerprint를 포함한다. 등록된 기준의 값과 해시, 비교 기준 실행 ID를 함께 제공하여 실패의 적용 조건을 유지한다.
- `registered_spec.json`, `result.json`, `verification.json`, `manifest.json`의 원본 경로와 해시, 완료 증거 해시를 보존한다. 원본 등록과 compact 기억이 다르면 거부한다. 새 기준의 해시가 원래 결과의 성공 여부를 소급 변경하지 않는다.
- 공통 문헌과 도구 계약은 각 독립 모델 요청에 한 번 포함한다. 현재 CLI 요청은 서로 독립적이므로 첫 요청에만 제공하고 이후 누락하는 방식은 사용하지 않는다. 기억마다 같은 본문을 다시 넣는 반복만 제거한다.
- 완료 및 확정 실패 요청의 원시 receipt에서 누적 입력·출력 토큰, 실제 모델 시간, 실제 CPU 시간을 읽고 출처를 연결한다. 실패 토큰이 제공되지 않으면 전체 토큰은 null이다. 캐시 재생은 새 사용량이 아니며, 다음 요청의 비용은 아직 측정되지 않았다고 표시한다.
- 모델은 증거, 검증 불확실성, 추가 정보의 가치와 실제 누적 비용을 함께 비교한다. 다른 가설 계열이나 명시적인 다음 실험 부재를 선택할 수 있다. 고정 반복 수, 연속 실패 횟수, 임의의 미세 개선 임계값을 추가하지 않았다.

저장된 원본 요청에 memory 직렬화만 적용한 [후향적 계산](../evidence/c-live-audit-v4/context-bytes/20261002T153452360892Z/serialization.json)에서는 마지막 요청의 UTF-8 크기가 223,282 bytes에서 110,914 bytes로 바뀌었다. 기억 부분은 192,215 bytes에서 79,847 bytes로 바뀌었다. compact 요청은 모델에 보내지 않았다. 새 비용 피드백 필드와 미래 문헌 코퍼스를 더하는 비용도 이 계산에 포함하지 않았다. 따라서 이 수치는 직렬화 결과이며 토큰·시간·가격 절감의 측정값이 아니다.

문헌 입력도 등록된 조건을 실제 사용하도록 변경했다. 제공된 `literature_snapshot`과 해시가 권위 있는 입력이다. ID·원본 URL·arXiv 버전 별칭의 중복은 별개 논문 수로 셀 수 없다. 요구된 서로 다른 기록 수보다 코퍼스가 작으면 모델 요청 전에 거부한다. 미래 코퍼스는 직접 확인한 원문의 범위를 명시한 [짧은 자체 작성 요약](../references/task_literature_v2.json)이다. 비 arXiv ID는 어댑터의 서지 식별자이며 arXiv 등록을 주장하지 않는다.

원본 Agent Laboratory의 `add_review`는 같은 ID를 다시 추가할 수 있고, 원본 완료 판정은 리스트 길이를 센다. 원본 AST 본문과 단계 흐름은 보존했다. 어댑터는 원본 알고리즘 완료 후 실제 목록의 ID, 요약, 등록된 출처와의 대응, 서로 다른 기록 수를 별도로 검사한다. 실패하면 `upstream_algorithm_status=success`와 원본 산출물을 보존하면서 `host_literature_contract_failure`로 분류한다. 제공된 요약에 접근했다는 증거를 논문 전체를 읽었다거나 모델 요약이 사실이라는 주장으로 확대하지 않는다. 원본의 missing-ID 문자열 반환도 확인되었으며, 그 문자열을 유효한 문헌 증거로 채택하지 않는다.

미래 비교의 회복·중복·기억 지표는 같은 정의를 사용한다. 실제 runtime 오류, 거부된 protocol, 검증 오류의 에피소드 뒤에 독립 검증된 CPU 성공이 오면 기술적인 회복으로 센다. 순서상 회복을 인과적인 수정 증거로 확대하지 않으며, 원인과 이후 성공을 모두 연결한다. 검증된 실행은 성공했지만 가설 기준을 충족하지 못한 경우는 기술 오류가 아니다. 명시적인 `retry_of`를 갖는 검증된 재시도와 실패 가설 재시도는 별도로 기록한다. 기억 hit는 모델 요청에 노출한 기록 수의 누적합이고, 고유 기록 수와 효과는 별개다. 중복 CPU는 양쪽 모두 `store.execution_fingerprint`로 계산한다. 기존 fingerprint는 가설 문구와 criterion을 이미 제외하며, 실제 소스·분할·seed·설정·모델·권한·자원 조건을 포함한다.

개발 복사본의 신규 계약 검사 11개는 실제 CPU 증거와 명시적인 provider fixture를 사용하며 모델을 호출하지 않는다. 문헌 중복·출처 부재, 원본 해시, compact 적용 조건, 실제 요청 비용의 unknown 처리, 가설 재시도와 기술 회복의 구분, 예산 소진과 외부 제공자 실패의 구분, 예산을 다시 소비하지 않는 완료 캐시 재생을 검사했다. 이는 구현 검증이다. 새로운 B/C 비교와 기억 확인 실험은 소스를 고정하고 별도의 사전 등록을 한 뒤 실제 모델·과제에서 평가해야 한다. 최종 과제나 현재 진행 중인 동결 실험을 수정하지 않는다.
