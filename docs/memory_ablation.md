# 사전 증거 검색 노출의 독립 비교 설계

상태: 검토 가능한 개발 설계다. 모델 호출, 실제 on/off 비교, 통계적 채택 판정은 아직 수행하지 않았다. 주 비교 실험의 동결된 `evidence_research` 패키지를 수정하지 않는다.

## 추정하려는 효과

같은 모델이 **다음 실험 하나를 선택할 때** 검증된 사전 실험 기록을 읽는 효과를 측정한다. 양쪽은 같은 공개 train/validation 자료, 모델 식별자, 명시적 reasoning effort, 문헌, 도구 권한, CPU/모델 요청 상한, 고정 실행기와 독립 평가기를 사용한다. 차이는 요청 객체의 `verified_memory` 값이다. ON에는 원본 증거에 연결된 검색 결과가 있고, OFF에는 빈 배열이 있다.

이는 호스트가 미리 생성한 알려진 보정 증거를 제공하는 통제 실험이다. 자유 연구에서 자연스럽게 축적한 기억의 효과, 다른 과제로 이전되는 기억, AgentRxiv 서버의 검색 품질, 일반적인 과학적 발견 성능을 입증하지 않는다. 두 조건 모두 Store의 중복 방지를 유지한다. 따라서 **중복 모델 제안**과 **실제 중복 CPU 실행**을 혼동하지 않는다.

## 정보 누출을 막는 단위

각 paired unit은 동일 보정 기록을 가진 두 독립 Store를 준비하고, 각각 한 번의 다음 실험 제안을 요청한다. 이 한 번은 사전에 정의한 진단 측정 단위이며 전체 Goal의 반복 상한이 아니다. 이후 주 연구 루프는 계속한다. 첫 제안만 평가하면 ON/OFF 사이의 이전 대화, 현재 best 값, 반복 피드백, 실행 횟수 표시 때문에 사전 기억이 우회 노출되는 문제를 피할 수 있다.

공유 요청에는 목표, 공개 task bundle, 문헌, 같은 literal config 계약, 같은 평가 규칙만 넣는다. best/config/보정 실행 횟수/실패 이유/이전 후보 피드백/Store 경로/owner 경로를 넣지 않는다. ON의 기억 안에만 설정·측정값·검증 상태·적용 조건·원본 result 경로와 해시가 있다. 모델의 도구 호출은 금지하고 원시 요청과 응답으로 독립 검사한다. read-only sandbox를 완전한 파일 읽기 격리로 표현하지 않는다.

각 응답은 `candidate` 한 개 또는 근거가 있는 `stop_reason`을 반환한다. 복수 후보나 형식 오류를 결과에 맞춰 고치지 않는다. 원본 오류를 실패한 진단 관측으로 보존하고 다음 독립 단위와 연구를 계속한다. 완료된 CPU 실행이나 모델 응답을 조용히 재실행하지 않는다. 알려지지 않은 실행은 재조정 전까지 보류한다.

## 실제 보정 기록

실행 전에 같은 literal config 목록, 순서, seed, 자료 해시, 소스 해시와 기준을 고정한다. 각각의 Store에서 같은 CPU 보정 실행을 실제로 수행해 비용과 시간을 따로 기록한다. 예를 들어 공개 회귀 과제에서 `(degree=1, alpha=0)`, `(degree=2, alpha=0)`, `(degree=8, alpha=100)`를 등록할 수 있다. 이 목록은 성능을 본 뒤 유리한 사례만 골라 바꾸지 않는다.

첫 보정은 측정된 baseline anchor다. 뒤 보정은 anchor 대비 개선이라는 등록 기준을 사용한다. 기준 충족 여부는 별도 평가기가 계산한다. 모든 보정이 성공하거나 실패할 수도 있으므로 양쪽에 필요한 성공·실패 기록이 항상 존재한다고 가정하지 않는다. `calibration_outcomes`에 실제 분포를 보존하고, 실패가 없는 단위의 실패 회피 지표는 null로 둔다. 가설 기준 미달과 CPU 실행 오류를 구분한다. 비교 결과를 관찰한 뒤 기록을 골라 버리거나 기준을 소급 변경하지 않는다.

CPU 보정은 양쪽의 공통 자원 봉투 안에서 동일 개수의 상한을 소비한다. 새로운 제안이 기존 조건과 같으면 Store가 원본 실행을 재사용한다. 추가 CPU 호출은 발생하지 않고 원본 증거가 연결된다. 알려진 실패 조건을 바꾸지 않고 다시 제안했는지는 별도 host 지표로 기록한다. 모델의 rationale, 예상 향상폭, 후보 점수는 proposal/inference로 남긴다.

## 사전 평가 항목

주 평가 항목은 독립 unit마다 `duplicate_OFF - duplicate_ON`이다. `duplicate`는 첫 유효 literal 제안의 실행 조건 fingerprint가 이미 완료된 보정 실행과 같으면 1, 새 조건이면 0이다. 분모는 사전에 등록된 다음 행동 결정 기회이며 후보 개수나 실제 실행 수에 따라 바뀌지 않는다. 원본 검증 증거에 연결된 목표 충족, 또는 명시적인 `no_justified_experiment` 이유를 가진 유효 중단 결정은 duplicate=0이다. 중단 이유는 모델의 계획 판단으로 남기고, 호스트가 저장된 실제 증거에서 선택한 best를 모델이 직접 찾아낸 결과라고 주장하지 않는다.

불법 응답, 외부 자원 부족, 알려지지 않은 실행은 별도 상태로 보존하며 성공으로 대체하지 않는다. 결과를 본 뒤 분모에서 지우지 않는다. 주 평가의 완전성 조건은 두 조건 모두 실제 모델 응답, 유효 literal 제안 또는 유효 중단 결정과 불변 보정 증거가 있어야 한다. 불완전 pair가 있으면 통계적 채택을 보류한다. 유효 중단을 임의로 실패로 바꾸거나 무효 pair를 지워 좋은 결과만 계산하지 않는다.

부 평가 항목은 다음과 같다.

- 새로운 실제 CPU 실행 개수, 실제 중복 CPU 실행 개수와 동일 조건 재사용 횟수.
- 제안한 실험의 실제 validation MSE 및 owner가 보관한 별도 test MSE. 중복 제안은 원본 보정 산출물로 계산한다.
- 등록 기준에 실패했던 보정 조건의 재제안 여부. 실패 보정이 없으면 null.
- 실제 provider input/output tokens, model seconds, CPU seconds, 보정 비용과 제안 비용. 비공개 billing은 null이며 누락된 실패 token usage를 0으로 만들지 않는다.
- 형식/권한 오류, 외부 자원 부족, 미결 실행의 개수와 원본 증거.

중복 감소만으로 과제 품질 향상이나 전체 프레임워크 개선을 선언하지 않는다. 하나의 주 항목을 사전에 고정하고 나머지는 탐색적 수치로 보고한다. memory ON이 추가 문맥 때문에 input tokens를 더 쓸 수 있으며 그 비용을 숨기지 않는다.

## 반복 및 확인 평가

먼저 사전에 정한 개발용 paired unit에서 실제 ablation pilot을 수집한다. B/C 주 비교의 분산을 이 다른 ON/OFF contrast의 분산으로 대입하지 않는다. 주 항목의 실제 paired delta와 고정된 의미 있는 감소폭·정밀도·검정력·variance-relative-SE를 `design_sample_size`에 넣는다. 부족한 pilot을 가짜 delta, 기존 논문 수치, 모의 응답으로 채우지 않는다.

확인 평가가 필요하면 pilot과 별도 공개 자료/owner test를 준비하고, 계산된 표본 수·순서·seed·소스·기준을 실행 전에 등록한다. 평가 결과가 구현 변경에 쓰이면 그 평가 자료를 개발 자료로 분류하고 새로운 확인 자료를 등록한다. 연구 루프 전체에는 고정된 반복 수·연속 실패 수·임의 실행 시간을 추가하지 않는다.

## 실행 도구의 범위

새 `scripts/memory_ablation.py`는 동결된 Engine/Store/runner/verifier/provider와 independent request audit를 재사용할 수 있다. import monkeypatch, 평가기 변경, 가짜 측정값, 평가 파일을 모델 입력에 넣는 방식은 사용하지 않는다. 최초 구현은 등록·CPU 보정·검증·raw model 요청 하나·원본 결과 수집·중단 재개만 제공한다. 자동 통계 채택과 일반적인 memory 효과 주장은 하지 않는다. 실제 모델 실행은 독립 검토 후 root가 시작한다.
