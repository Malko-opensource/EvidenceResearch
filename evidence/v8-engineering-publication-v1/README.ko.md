v8 일반 소스와 engineering 증거의 공개 후보다. 이 목록은 공개 수행 자체가 아니다.

설치된 소스 111개 중 일반 소스 73개를 선택한다. 원본 upstream runtime 파일 35개와 선택적인 과거 예제 3개는 제외했다. 새 v8 예제는 미래 메타데이터이며 units=[]다. 고정 upstream 35개는 공개 소스의 scripts/fetch_upstream.py 및 references/manifest.json으로 별도 취득·인증해야 한다.

자체 새 환경의 6단계·276개 시험 원시 로그, 고정 c8 소스의 whole276 증거, 독립 10계열·28사례의 합성 fixture 결과를 포함한다. 시험들은 서로 다른 검증 질문이다. 독립 native B/C 검사는 초기 handoff와 증거 계약을 다루며 전체 연구 흐름 성공이나 실제 보고서 완결성을 증명하지 않는다. 모든 구성 fixture의 actual/adoption 자격은 false다. v8 peer의 첫 로그 파서 실패와 별도 이어서 확인한 통과 기록을 수정 없이 보존한다.

독립 capsule에서 package20/reference3와 선택한 helper·pin·로그를 전달한다. 원 manifest는 exact 보존하지만 그 원래 전체 목록의 일부를 전달하지 않는다. 제외한 원 등록 본문, native 등록 payload, upstream35, 외부 synthetic output tree 때문에 이 부분만으로 전체 fixture 재실행 가능하다고 주장하지 않는다. whole/설치/peer helper에도 원래 로컬 경로 의존성이 있어 그 파일은 원 실행 소스 증거이며 일반 portable replay 명령이 아니다. 새 공개 checkout에서 전체 설치·fixture 재현을 확인한 별도 proof도 여기서는 주장하지 않는다.

원 릴리스 도구의 좁은 수정은 sources_baseline이 작성하고 root가 독립 검토했다. 설치 산출물 검토도 그 수정 작성자가 수행했음을 명시한다. 별도의 c8 10계열 검사는 package 구현에 참여하지 않은 검토자가 작성했다. 원 source와 로그는 정확한 SHA로 연결한다.

보호된 과거 파일 목록은 source-only metadata이며 이 게시 준비에서 과거 실제 연구 파일을 열지 않았다. 실제 v4 추가/v5/v6/v7/v8/v9 기록, owner 자료·request·secure config·등록 원문·private generation 값은 선택하지 않는다. 원 c8 method 및 c9 등록의 실제 개발 observation 경로/본문을 전달하지 않고 source/method hash와 범위만 기록한다.

검증 가드는 Python 훅이며 OS 전체 sandbox가 아니다. 허용된 작은 CPU 하위 프로세스 하나는 부모 훅 적용 밖이다. 새 모델·연구 CPU·환경·CLI·시험·Git·인증·게시 실행은 하지 않았다. 이 engineering 통과는 실제 보고서 완결성, 연구 개선, 최종 평가, Goal 완료를 의미하지 않는다. 선택한 실행 범위에서 실제 v8 연구 등록은 없으며 c9은 게시 범위 밖의 변경 중인 로컬 후보다.
