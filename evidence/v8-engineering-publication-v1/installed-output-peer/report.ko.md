v8 새 환경 설치 산출물의 읽기 전용 검토를 통과했다. 원 릴리스 도구의 좁은 참조 개수 수정은 이 검토자가 작성했으며, 부모가 그 구현을 별도로 검토했다. 따라서 이 문서는 도구 구현에 대한 독립 검토가 아니라, 새 설치 파일과 저장된 실행 결과를 대조한 검토다.

외부 핀으로 인증한 c8 원본 110개에 문서 2개를 명시적으로 대체하고 미래 실행 메타데이터 1개를 추가한 v8 파일 111개를 확인했다. 패키지 모듈 20개, 참조 전체 40개, 실행·해시 closure 38개, closure 밖에도 인증·보존된 README/LICENSE 2개가 일치한다. 원본 upstream 35개의 SHA·길이·Git blob도 대조했다. 자체 venv 경로, user_site=False, 패키지 버전 0.4.1.dev0와 런타임 출력이 일치했다.

부모가 실행한 6단계의 명령·종료 코드·영수증·stdout/stderr SHA와 최종 원시 unittest 로그를 확인했다. 시험 시작 276개, 성공 completion 276개, `Ran 276 ... OK`가 일치했다. 첫 외부 검토는 `... ok`를 한 줄로 가정한 파서 때문에 실패했다. 원본 upstream 파싱 시험 하나에서 SyntaxWarning이 `...`와 `ok` 사이에 삽입돼 있었으며, 실제 시험 실패가 아니다. 첫 도구·실패 결과·원시 로그를 수정하지 않고, 남은 해당 로그 파싱·가드·최종 파일 변동 검사만 별도 도구로 마쳤다. 환경·설치·CLI·시험은 재실행하지 않았다.

검증 가드의 금지 접근·비fixture 프로세스·네트워크 카운터는 모두 0이고, 허용한 작은 CPU fixture 하위 프로세스는 1개다. 그 하위 프로세스는 PYTHONPATH를 바꿔 부모 Python 훅 적용 밖이다. 이것은 OS 전체 sandbox 또는 모든 형제 경로 접근 부재의 증명이 아니다. 이 검토 자체의 파일 읽기 허용 목록·프로세스·네트워크·directory discovery 카운터는 모두 0이다.

보호된 기존 417개는 저장된 before/after 해시 목록의 일치만 확인했으며, 원본 본문을 열지 않았다. 새 실제 모델·연구 CPU·owner 자료·Git·게시·환경·시험·CLI 실행은 0이다. 인증 또는 실제 provider 접근 성공을 확인한 것은 아니다. 설치와 구성 시험의 성공은 프레임워크 개선 효과나 Goal 완료를 의미하지 않는다.

최종 판정은 complete-result.json이며, 초기 실패 result.json은 그대로 보존했다. 정확한 파일 목록과 SHA는 manifest.json에 있다.
